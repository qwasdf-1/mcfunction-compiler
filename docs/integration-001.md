### Verification protocol, first extraction

The candidate CI overlays only the pinned checkpoint's scripts in a disposable runner workspace; old research workflow/test history is not copied into the branch. Native IR043–047, IR047 pure/mixed A/B and original publisher regression run against candidate runtime. IR047 additionally compares all archived checkpoint case maps and diagnostic counters. CPU gate fields must be inspected, not inferred from job success. The default-off screen uses actual main and candidate builds on one runner, eight independent sequential boots in two counterbalanced four-boot blocks (MCCM/CMMC), no FC_* variables, fresh worlds/config and frozen simulation. Exact native quota snapshots and full work state each window; 1024 blocks of score mutation, two-stage guard and two native nested calls. One fixed calibrated batch count, >=500ms CPU per measured window, six stable warmups, two holdouts, eight measured windows, <=5% spread and <=5% between-boot A/A in both arms; both candidate/main block median ratios <=1.05. Inconclusive is not passing. This is a bounded default-off screen, not an equivalence proof for all workloads or a clean vanilla/no-mod control. Opt-in checkpoint-vs-candidate absolute CPU and package/config cleanup remain later gates.
