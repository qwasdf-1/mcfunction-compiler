# IR-039 — Compound score predicates, ordered control flow and dominance CSE

**Status: ACCEPTED — corrected compound predicate implementation passed expanded native semantic acceptance (2026-11-24).** Work remains on draft PR #10, `work/compiler-coverage`. No production default changes.

## Scope

One source command may contain two to eight consecutive literal score `if` / `unless` stages followed by a supported typed scoreboard mutation or binary operation. Range and comparison stages can be mixed. Fake holders and independently opted-in `@s` are supported; arbitrary selectors, context-changing modifiers, calls, returns, division/modulo/swap, mixed execute modifiers and longer chains remain native. Enable `FC_TYPED_IR_COMPOUND_SCORE=true` with the typed namespace/mode and `FC_TYPED_IR_EXTENDED_SCORE=true`. Existing range and self-holder flags still control their own coverage. No legacy callback-rewriting prototype is composed with this path.

## Representation and optimization

`TypedScoreIR.Compound` retains one original command, a terminal instruction, and an immutable ordered predicate list. The effects union includes all guard operands and terminal reads/writes. `CompoundScoreIR.Plan` interns exact symbolic score slots and objective names, and records each original stage as READ, KNOWN_PASS or KNOWN_FAIL. Only exact polarity-independent predicate keys (holder identities, objective names, validated range text or comparison operator/operands) are reused. A later reached stage is dominated by every earlier successful stage, so identical polarity can be proven true and opposite polarity false. No modifier debit is deleted. Every predicate reached with a source retains its debit and short-circuit branch. After a failed predicate the remaining original redirect stages still consume their debits without reading any further scores, matching the native empty-source modifier loop. Missing rows are false before inversion; no row is created by a predicate. A same-slot comparison uses one read. Distinct `@s` and fake-holder keys are never assumed to alias, and `@s` resolves against the actual invocation source.

The new parser inspects the untouched Brigadier redirect chain and validates every score modifier and the terminal. It uses source shape solely for admission and identity checks, then wraps a detached terminal context for the existing terminal validators. A rejected or cost-selected-native compound retains its original BuildContexts action; no live parsed callback is rewritten.

The interpreter uses ordered stage primitives. ASM emits an unrolled sequence of branch targets, a direct read-stage call or a constant-result stage call, and the terminal debit/mutation path. Runtime preflight resolves unique objective names and holders afresh for each source command. No scoreboard values or objective references survive as valid data across commands. On absent objectives/holders, read-only target, fork limit at or below one, tracing or non-empty result callback, preflight queues the original native action followed by the remaining source cursor **before any debit or mutation**. This conservative eager preflight may decline a chain even if an invalid later reference would be short-circuited; the original vanilla action decides that branch. It must not replay partially executed compiled stages.

## Acceptance

The new five-JVM differential compares uncompiled vanilla, compound-disabled bytecode (same other feature flags), compound interpreter, generated bytecode and direct scheduling. The original suite exercised nine new and four inherited functions at full quota and nine cutoffs (150 observations per mode). The expanded suite adds an eight-stage failure-position fixture, every quota 1–40 and 48 plus full quota. The two dynamic fixtures run with a real armor stand source and without an entity (672 observations per mode). The oracle checks native state, missing rows, original opaque barriers, actual typed coverage, positive reached-stage/reuse/short-circuit/native-fallback/empty-stage-debit counters in enabled modes and zero in the disabled control. Source-contract checks assert original-chain preservation and explicit ASM branches. Existing IR-008 and IR-013 suites remain regression gates. Archive all results and logs, including failures. No CPU timing inference or production promotion.

## Limits

Pure same-thread scoreboard read behavior is assumed between the supported pure score predicates. The plan does not fold algebraically equivalent but syntactically different ranges, reorder predicates, propagate values across commands, or compile arbitrary execute modifiers. The existing cost model only counts compound commands as guarded commands, not individual stages; its uncalibrated weights remain opt-in. Preflight scratch arrays and extra compile-time metadata are a tradeoff. Dynamic holder resolution and fallback are subject to the actual native acceptance results, not merely the static contracts.

### Root cause and corrective implementation

The original mapped Minecraft 26.3 [IR-025 bytecode archive](https://github.com/qwasdf-1/mcfunction-compiler/actions/runs/44871381290/artifacts/14694236421) resolves the question. In `BuildContexts.execute`, offsets 130–136 debit every non-null redirect; 155–171 iterate the source list (which may already be empty); 303–314 install the next list and advance the stage; only at 343–377 is empty-source completion tested. There is no intra-modifier quota check. `ExecutionContext.runCommandQueue` gates the next queued action at quota <=0; `ExecuteCommand.execute` debits its terminal separately. `ExecutionContext.incrementCost` simply decrements the integer field. Thus a failed score predicate kills all subsequent *evaluations*, not their modifier debits. This is distinct from the earlier single-guard model.

The correction charges the remaining empty-source suffix without performing predicate reads, removes the premature intra-modifier quota gates, retains the terminal quota gate, and makes the known-stage bytecode pass its original index. The native fork-limit test is also relevant even with one source: when forkLimit <=1, conservatively defer the untouched chain before any debit. The `ir039_empty_stage_debits` diagnostic counts actual suffix debits restored, not optimized reads. The expanded oracle pins the failed quota-12 boundary, adds first/middle/last failure at eight stages, sweeps all nearby cutoffs, and collects cross-arm state differences for the complete matrix rather than stopping on the first such mismatch. No acceptance criterion was relaxed.
