## A — cross-command optimization (recommended first)

The frozen wrap source contains ten ordered two-stage score guards, each testing @s erb.radius (3/6/8/10/12) then @s erb.cursor (upper bound 123/925/2109/4169/7153 or ..-1), terminal set cursor to zero or upper bound minus one. All ten reached 17245 times, only line index 8 had two terminal callbacks. 172448/172450 no terminal. Current TypedScoreIRRuntime.State.begin checks quota and queued-work epoch every command; startCompound resolves objective names and dynamic holders afresh, resets compoundVisited/Present, checks tracer/callback/fork limit, delegates native before any effects on missing objectives/holder or read-only target. compoundBranch charges every remaining stage on empty-source path. compoundTerminal separately checks quota and charges terminal before score access. TypedIROptimizer and TypedIREffectAnalysis deliberately do not eliminate/reorder command boundaries.

Propose new gated immutable run plan for consecutive validated compound pure-score guards with identical resolved source and exact symbolic read slots. Begin with homogeneous two-range guards/ordinary set, not arbitrary commands. Reuse value AND absence only across completed pure failed guard boundaries. Keep per-command quota/epoch checks, all modifier debits including empty stages, original short-circuit order, fallback, trace/callback/error behavior. Invalidate all local facts BEFORE any terminal row creation, score access/mutation, callback, feedback, native fallback, opaque command or yield; never cache ScoreAccess. On positive guard with exhausted quota, stop with no terminal. No cross-invocation/global cache or write-side hooks. Require reentrant-safe mode; decline tracer, nonempty callback, restrictive fork limit, unsupported shape. Keep native fallback before effects and conservative eager preflight; potential later shared objective/holder preflight is a distinct measured change. Arbitrary modded side effects on score reads are outside scoped vanilla purity assumptions. IR010 revision-cache pilot (no established gain) is not an appropriate backend; IR040 is intra-command only.

Offline abstract differential on exact 10-source sequence, 11 radii (including absent/INT extrema), 22 distinct cursor values (including absence/bounds/extrema), quota 0..25, six simulated synchronous listener variants: 37752 modeled cases, exact matching final values, write order, quota/debits. Reuse resets before each modeled write. For recognized radius/normal cursor no write, 10 radius + 2 cursor reads -> 1 + 1; absent radius 10 -> 1; radius12 cursor7153 12 -> 4; radius3 cursor-1 12 -> 3. Both modifiers still debit 20 per full no-write call. Conditional estimate 172450 - 17245 - 2 = 155203 avoided radius lookups alone at observed historical terminal pattern, assuming normal preflight and same invocation grouping. Not a CPU result, nor proof of Java/native implementation. No claim of exact cursor savings without radius/row distribution.

## B — context-transforming static function dispatch

Four exact execute as <selector> at @s run function <id> sites: runtime/finish danger, quiet, waiting (454 visits each) and runtime_tick player tick (601); 1963 parent visits. One leading score guard + as + at in source/tick_dimension (601), two as + score guard sites (2+1); all transforming forms 2567 visits, remaining two unsupported function dispatch visits are entity-condition-only. Macro entry zero separately. Native ordinary callback field is zero for these custom executor terminals; NOT zero child tasks. No per-site selected-source count available in frozen census, so fanout and CPU budget unknown. Avoid conflating with 647279 terminal callbacks from separate IR025 as-score-set fork (IR028 inconclusive, IR029 retained native scan dominant).

Mapped BuildContexts offsets 130–317: every non-null modifier charges one debit, even empty list, cumulative next-source size >= fork limit errors on original source; forked modifier errors report on current transformed source and continue, non-forked error aborts. Finish at offsets 378–464: CustomCommandExecutor.run invoked immediately in native source order with one ExecutionControl, actual terminal ContextChain and accumulated ChainModifiers; NOT ordinary deferred ExecuteCommand/ContinuationTask. No added terminal debit or quota check mid chain. Native source transformation order as then at differs from at then as: position/dimension/rotation and selector anchor matter. Never move, fuse, cache or reselect live selectors; retain native parsed modifiers and exact vanilla callback/terminal identity. A narrow typed X boundary may predecode two validated modifiers and eliminate generic chain stepping/avoidable allocations; keep native selection, mapping and native custom terminal. Trace/result/return/restrictive limit fall back before effects; exclude chained/other transformations and macros initially. For 0/1/N sources use native ordering, cumulative cardinality and error semantics; invoke terminal for all transformed sources before child actions execute. No direct cursor. Later extend leading guard or as-score only after gate.

Before implementation, diagnostic attribute selected sources and actual child tasks to exact parent sites in the pinned pack; determine whether 0/1/N is common (a headless @a may select none). Controlled CPU split 0,1,4+ sources, matching child IDs, executor UUID/order, dimensions/position/rotation, missing function, mutation between selections, score conditions, nested callbacks, real quota cuts and fork-limit failures. Compare native/IR043 baseline versus X, not hypothetical source counts. No persistent selector index. Lower priority than A given exposure and retained work, but useful next independent feature.

## C — singleton execution specialization

Actual IR045 parsed ledger S = 11 validated isolated sites, 6 reached, 1091 visits, 1061 ordinary callbacks. Bare add/set at runtime_tick (601) and runtime/finish (454) = 1055 visits; 3 binary sites x2=6; dormant compound guard 30 visits/0 callbacks. Five other S sites unreached. Separately plain self-tag V sites 7, 5776 visits, primarily capture/store (5769); one other selector tag visit, not included in narrow self-tag family. IR041 full-pack source screen: Blastback 15474 eligible shapes, 562 region-eligible lines, 14912 syntactically isolated candidates (~96.37%); Vein Miner 170/136/34. This is static syntax only, not parsed admission, actual reach or profitability. Many generated functions are not in 17-function native census. Need bounded native call-frequency/source-shape survey in generated read/write/restore paths and representative second pack before selecting singleton.

MixedFunctionIR.flush deliberately emits exact original action for size1, TypedScoreIR.Program and TypedRegion require 2..64, directBytecodeChunks excludes singletons and functions shorter than 2. Existing IR011 singleton feedback optimization is unrelated, no established CPU gain. Do not simply lower minimum region length, generate one hidden class per static singleton, or relax direct cursor. First try explicit typed U boundary, one original position, prepared reusable Java executor (no per-site generated class), narrow bare literal add/set/remove, then binary/guard only with evidence. Preserve native queue semantics and exact original fallback for tracing/callback/reentrant/invalid state, quota and feedback. Compare native, prepared singleton and (only if useful) generated singleton on exact one-command functions and mixed V/U/D/G/T neighbors. Separate plain-tag candidate, native terminal preserved initially. Measure cold compile CPU, memory/class count, repeated execution CPU, break-even, and positive fallback/queue-order differential. If no incremental gain, retain S native. Do not enable all generated functions from static screen.
