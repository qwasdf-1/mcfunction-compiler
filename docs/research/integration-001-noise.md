## Mechanistic evidence

- Absolute pure/mixed: 16/16 boots individually complete; maximum timed spread 1.45%/1.53%. Same-binary medians differ across fresh JVMs (pure checkpoint 5971.734 vs 5540.395 ms in block 2, mixed candidate 5132.269 vs 4696.269 ms in block 2). Pure candidate A/A <=1.25% in both blocks; not evidence of a uniform host effect or uniform compiler difference.
- Default-off boot 0 main timed spread 5.11%, boot 1 candidate 5.32%, boot 2 candidate 5.82%; boot 5 main combined last-six warmup plus holdout spread 18.50% (one 4886.36 ms holdout vs 4103.61–4284.94 ms plateau). Candidate boot 2 system CPU pressure spikes 1200.663 and 1428.887 ms over ~4.38s windows, vs typical ~15–20 ms; server wait remained below 0.5 ms there. Host pressure is observed, not a proof of attribution.
- Pure incremental boot 2 baseline combined holdout spread 5.04% (1386.106–1456.700 ms, median 1402.03 ms), reuse 4.54%; baseline narrowly failed 5%. Do not round it down, remove the window or treat one qualified boot as acceptance.
- Across 559 warmup, holdout and timed windows in the five archives (excludes calibration), no reported cgroup throttling or process-affinity change; 99 windows with incomplete per-surviving-thread accounting, because transient threads are not fully covered. Absolute pure/mixed median GC-worker CPU per timed window ~62–94/~45–60 ms across boots, typically ~1–2% of server CPU; not the earlier SCHED-NOISE-005 sustained anomalous GC regime. Isolated JIT bursts reached ~590 ms; stable boot medians often had only single-digit ms JIT-worker CPU. No evidence establishes GC, JIT tier, host frequency or scheduler migration as sole cause. Old affinity snapshots are JVM process masks [0,1,2,3], not actual Server thread placement. CPU frequency, steal-time, thread migration and hardware performance counters were absent. Zero quota throttling does not imply absence of hypervisor contention or frequency changes. See [noise-control standard](benchmark-noise-control-standard-v0.1.md).

## Predeclared retry, before executing

One bounded retry of ONLY the four inconclusive suites: pure incremental, final default-off, absolute pure, absolute mixed. No changes to source runtime, exact work, original command dispatch, quota parity, diagnostic preflight, treatment toggles, sample/boot order or counts, timing metric, calibration/warmup/holdout procedure, 5% A/A/stability/nonregression gates or incremental effect threshold. No selection of successful subsets and no automatic repeated attempts. The final mixed incremental accepted result and semantic results are retained; these are unchanged runtime builds, with an explicitly different controlled measurement environment.

Intervention: deterministic Linux thread placement on the same guest, at least four allowed logical CPUs. Reserve last allowed logical CPU and any visible SMT siblings; launch controller and JVM/Gradle children on up to three other logical CPUs, preferring different visible cores. Set actual Server thread affinity to singleton CPU after server startup and before calibration; preserve original four-vCPU JVM ergonomics with -XX:ActiveProcessorCount=4 on BOTH arms. Does not guarantee exclusive physical core or hypervisor topology; auxiliary threads born from the Server thread may inherit its mask, so report observed overlaps. Capture singleton affinity (hard fail on drift), last CPU and migration counters, visible sibling topology, per-CPU proc-stat deltas including steal, endpoint CPU frequency/governor if exposed, GC/JIT CPU and wait, pressure, JVM/host/build fingerprints. No frequency correction, GC subtraction, adaptive window deletion, additional runtime instrumentation or changed heap limits. Loom runServer uses development classes/resources; fingerprints record those as well as built JARs. Endpoint frequency is not continuous sampling. Unavailable fields remain null.

Workflow defaults to a hosted runner, not a dedicated host. Dedicated Linux x64 runner with compiler-benchmark label can be selected via manual workflow dispatch, with host isolation configured by the operator (fixed physical-core selection, consistent governor, no concurrent workloads). Connector cannot enumerate registered runners; no claim such a runner exists. If controlled hosted retry remains unqualified, stop hosted retries and use a dedicated runner after provisioning; report residual ambiguity even if acceptance passes. Do not modify compiler implementation solely on noisy results.
