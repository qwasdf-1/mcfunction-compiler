# IR-039 — Compound score predicates, ordered control flow and dominance CSE

**Status: implementation committed; native semantic acceptance pending.** Work remains on draft PR #10, `work/compiler-coverage`. No production default changes.

## Scope

One source command may contain two to eight consecutive literal score `if` / `unless` stages followed by a supported typed scoreboard mutation or binary operation. Range and comparison stages can be mixed. Fake holders and independently opted-in `@s` are supported; arbitrary selectors, context-changing modifiers, calls, returns, division/modulo/swap, mixed execute modifiers and longer chains remain native. Enable `FC_TYPED_IR_COMPOUND_SCORE=true` with the typed namespace/mode and `FC_TYPED_IR_EXTENDED_SCORE=true`. Existing range and self-holder flags still control their own coverage. No legacy callback-rewriting prototype is composed with this path.

## Representation and optimization

`TypedScoreIR.Compound` retains one original command, a terminal instruction, and an immutable ordered predicate list. The effects union includes all guard operands and terminal reads/writes. `CompoundScoreIR.Plan` interns exact symbolic score slots and objective names, and records each original stage as READ, KNOWN_PASS or KNOWN_FAIL. Only exact polarity-independent predicate keys (holder identities, objective names, validated range text or comparison operator/operands) are reused. A later reached stage is dominated by every earlier successful stage, so identical polarity can be proven true and opposite polarity false. No stage is deleted: every reached stage retains its modifier debit and short-circuit branch. Missing rows are false before inversion; no row is created by a predicate. A same-slot comparison uses one read. Distinct `@s` and fake-holder keys are never assumed to alias, and `@s` resolves against the actual invocation source.

The new parser inspects the untouched Brigadier redirect chain and validates every score modifier and the terminal. It uses source shape solely for admission and identity checks, then wraps a detached terminal context for the existing terminal validators. A rejected or cost-selected-native compound retains its original BuildContexts action; no live parsed callback is rewritten.

The interpreter uses ordered stage primitives. ASM emits an unrolled sequence of branch targets, a direct read-stage call or a constant-result stage call, and the terminal debit/mutation path. Runtime preflight resolves unique objective names and holders afresh for each source command. No scoreboard values or objective references survive as valid data across commands. On absent objectives/holders, read-only target, tracing or non-empty result callback, preflight queues the original native action followed by the remaining source cursor **before any debit or mutation**. This conservative eager preflight may decline a chain even if an invalid later reference would be short-circuited; the original vanilla action decides that branch. It must not replay partially executed compiled stages.

## Acceptance

The new five-JVM differential compares uncompiled vanilla, compound-disabled bytecode (same other feature flags), compound interpreter, generated bytecode and direct scheduling. Nine new and four inherited functions are exercised at full quota and nine cutoffs; the two dynamic fixtures run both with a real new armor stand as source and without an entity (150 observations per mode). The oracle checks native state, missing rows, original opaque barriers, actual typed coverage, positive reached-stage/reuse/short-circuit/native-fallback counters in enabled modes and zero in the disabled control. Source-contract checks assert original-chain preservation and explicit ASM branches. Existing IR-008 and IR-013 suites remain regression gates. Archive all results and logs, including failures. No CPU timing inference or production promotion.

## Limits

Pure same-thread scoreboard read behavior is assumed between the supported pure score predicates. The plan does not fold algebraically equivalent but syntactically different ranges, reorder predicates, propagate values across commands, or compile arbitrary execute modifiers. The existing cost model only counts compound commands as guarded commands, not individual stages; its uncalibrated weights remain opt-in. Preflight scratch arrays and extra compile-time metadata are a tradeoff. Dynamic holder resolution and fallback are subject to the actual native acceptance results, not merely the static contracts.
